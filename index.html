        §1 · foundations
        
      
        Why structure beats prose
        
      
        
        A model that gets a wall of prose has to infer three things at once: who it's playing,
        what it's optimizing for, and what shape the output should take. A model that gets a frame
        only has to fill them. Composer's R-G-C-B-T-S frame
        — Role · Goal · Context · Bounds · Task · Success — is one such frame, but the deeper rule
        is just: separate the slots so the model can't confuse them.
      
        
      
        
        The rest of this guide is the toolkit you slot into that frame: techniques that change
        how the model reasons (chain-of-thought, self-consistency), how it acts (ReAct, reflexion),
        and how multiple models compose into a system bigger than any single context window.

        §2 · single-prompt techniques
        
      
        Eleven techniques worth knowing by name
        
      
        
        Ordered roughly by complexity. The first two are baselines every later technique is measured against.
        Each card cites a single primary source — read it before you commit to the pattern in production.
      
        

      
        

        
        
          
        
            
        Zero-shot prompting
        
            Brown et al. · 2020
          
        
          
        Asking a model to perform a task using only a natural-language instruction, with no worked examples. Works well on tasks the base model has seen heavily in pre-training; degrades on tasks with unusual formats or domain conventions.
        
          
        When to use: The task is common (summarize, translate, classify into obvious labels) and you want the shortest possible prompt.
        
          
        Classify the sentiment of this review as positive, negative, or neutral:
"{review}"
        
          
        Language Models are Few-Shot Learners ↗
        
        
        

        
        
          
        
            
        Few-shot prompting · in-context learning
        
            Brown et al. · 2020
          
        
          
        Include a small number of input/output demonstrations in the prompt so the model infers the task pattern at inference time, with no weight updates. Sensitive to example selection, ordering, and label distribution; benefits saturate quickly past ~8–16 examples for most tasks.
        
          
        When to use: Output format is non-obvious (custom JSON, niche labels, particular tone) and you can show 2–8 representative examples.
        
          
        Q: 2+2   A: 4
Q: 7+5   A: 12
Q: 13+9  A:
        
          
        Language Models are Few-Shot Learners ↗
        
        
        

        
        
          
        
            
        Chain-of-Thought (CoT)
        
            Wei et al. · 2022
          
        
          
        Prompt the model to produce intermediate reasoning steps before its final answer, typically by showing exemplars that include such steps. The original paper reports gains mainly on arithmetic, commonsense, and symbolic reasoning, and only at sufficient model scale (roughly 60B+ params in the 2022 evaluation) — smaller models can be neutral or hurt by it.
        
          
        When to use: Multi-step arithmetic, logic, or planning on a capable model where you can tolerate longer outputs.
        
          
        Q: Roger has 5 balls. He buys 2 cans of 3 balls each. How many balls?
A: Roger starts with 5. 2 cans of 3 is 6. 5 + 6 = 11. Answer: 11.
Q: {your question}
A:
        
          
        Chain-of-Thought Prompting Elicits Reasoning ↗
        
        
        

        
        
          
        
            
        Self-Consistency
        
            Wang et al. · 2022
          
        
          
        Sample multiple chain-of-thought reasoning paths at non-zero temperature, then take a majority vote over the final answers instead of using a single greedy decode. Improves reasoning accuracy on benchmarks like GSM8K (+17.9 points reported), but multiplies inference cost by the sample count and only works when the answer space supports voting.
        
          
        When to use: Reasoning tasks where the answer is a short discrete value (number, label, multiple-choice letter) and you can afford N parallel completions.
        
          
        # Run the same CoT prompt N times at temperature=0.7
final_answer = majority_vote([extract(c) for c in completions])
        
          
        Self-Consistency Improves CoT Reasoning ↗
        
        
        

        
        
          
        
            
        Tree-of-Thoughts (ToT)
        
            Yao et al. · 2023
          
        
          
        Generalizes chain-of-thought into a search tree where the model proposes multiple candidate "thoughts" at each step, evaluates them, and expands or backtracks. Requires an explicit controller (BFS/DFS plus a value function) wrapped around the model, so it is an orchestration pattern, not a single prompt; cost scales with branching factor and depth.
        
          
        When to use: Problems where solutions need exploration and the model can reasonably evaluate its own partial progress (Game of 24, creative writing with constraints, crosswords).
        
          
        Step:  "Propose 3 next moves toward the goal. One-line rationale each."
Eval:  "Rate each candidate sure / maybe / impossible toward solving {task}."
Loop:  expand top-k, prune the rest, repeat until depth D.
        
          
        Tree of Thoughts: Deliberate Problem Solving ↗
        
        
        

        
        
          
        
            
        ReAct
        
            Yao et al. · 2022
          
        
          
        Interleaves reasoning traces (Thought:) with tool-use actions (Action:) and their results (Observation:) in a single loop, so the model can ground reasoning in retrieved facts. Reduces hallucination on knowledge tasks but adds latency per step and depends on having reliable tools and a stop condition.
        
          
        When to use: Tasks where the model must look things up or operate on an environment (search, browsing, API calls, code execution) rather than answer from parametric knowledge alone.
        
          
        Thought: I need the population of Lyon.
Action: search("Lyon population")
Observation: ~522,000 (2023)
Thought: That answers the question.
Answer: ~522,000
        
          
        ReAct: Synergizing Reasoning and Acting ↗
        
        
        

        
        
          
        
            
        Reflexion
        
            Shinn et al. · 2023
          
        
          
        After an agent attempt fails (per an external evaluator or unit test), the model writes a short natural-language critique of what went wrong and stores it in an episodic memory that is prepended to the next attempt. Improves iteratively on tasks with a clear success signal; without that signal, "reflection" is unverified self-talk and can entrench mistakes.
        
          
        When to use: Agentic loops with a checkable verdict per attempt (passing tests, reaching a goal state, a reward score) and budget for multiple tries.
        
          
        attempt_1 -> fail
reflect:   "I assumed the index was 1-based; it is 0-based."
attempt_2: <prior reflections + original task>
        
          
        Reflexion: Verbal Reinforcement Learning ↗
        
        
        

        
        
          
        
            
        Role / persona prompting
        
            Anthropic docs
          
        
          
        Set a role for the model in the system prompt to focus its tone, vocabulary, and default behaviors for a use case. Anthropic notes that even a single sentence shifts behavior measurably — but role prompting does not unlock new capabilities and does not reliably bypass safety training.
        
          
        When to use: You want a consistent voice or domain framing across many turns ("code reviewer", "patient-facing triage nurse") without restating it each message.
        
          
        system: You are a senior SRE running a calm, blameless post-mortem.
        Prefer concrete timelines and falsifiable claims.
user:   Here is the incident transcript: ...
        
          
        Anthropic — Prompting best practices (system prompts) ↗
        
        
        

        
        
          
        
            
        Chain-of-Density
        
            Adams et al. · 2023
          
        
          
        Iteratively rewrites a summary at fixed length, each pass adding 1–3 previously missing salient entities without growing the word count, so the final summary is denser and more abstractive. Human raters prefer denser summaries up to a point, then readability degrades — a real density/readability tradeoff to tune.
        
          
        When to use: Producing a short, information-dense summary of a long article when entity coverage matters more than narrative flow.
        
          
        Summarize the article in 5 sentences. Then repeat 4 more times.
Each iteration: keep length identical, add 1–3 missing salient
entities, remove filler. Output all 5 versions as a JSON list.
        
          
        From Sparse to Dense: Chain of Density ↗
        
        
        

        
        
          
        
            
        Structured output · JSON schema mode
        
            OpenAI · 2024
          
        
          
        Constrains decoding so the response is guaranteed to be valid JSON matching a supplied JSON Schema. OpenAI's Structured Outputs feature enforces adherence at the decoding layer — not by prompt instruction — trading some flexibility (schema specified up front, some JSON Schema features unsupported) for reliable parsing.
        
          
        When to use: Any downstream code path that needs to JSON.parse the response or hand it to a typed function — extraction, classification with metadata, tool-call arguments.
        
          
        response_format = { "type": "json_schema",
  "json_schema": { "name": "Ticket", "strict": true,
    "schema": { "type": "object",
      "properties": { "severity": {"enum":["low","med","high"]},
                      "summary":  {"type":"string"} },
      "required": ["severity","summary"],
      "additionalProperties": false } } }
        
          
        OpenAI — Structured Outputs in the API ↗
        
        
        

        
        
          
        
            
        Prompt chaining
        
            Anthropic docs
          
        
          
        Split a task into a sequence of separate model calls, where each call's output feeds the next, instead of asking for everything in one prompt. The most common pattern is self-correction — draft → critique → revise. Worth the added latency mainly when you need to inspect, log, or branch on intermediate outputs.
        
          
        When to use: The pipeline has distinct stages with different instructions, you want to evaluate or gate between them, or a single prompt is hitting context/quality limits.
        
          
        call_1: extract claims from {doc} -> claims.json
call_2: for each claim, verify against {source} -> verdicts.json
call_3: write report using verdicts.json
        
          
        Anthropic — Chain complex prompts ↗
        
        
        

      
        
    
        

    
    
        
      
        §3 · agent orchestration patterns
        
      
        Seven shapes a multi-agent system can take
        
      
        
        Each pattern names a topology (who talks to whom) and a termination rule (when the system stops).
        Most production systems combine two or three — e.g. an orchestrator-worker whose orchestrator
        runs an internal reflection loop.
      
        

      
        

        
        
          
        
            
        Orchestrator-worker
        
            Anthropic · 2024
          
        
          
        Shape: A central LLM (orchestrator) inspects the task, dynamically decomposes it into subtasks, and dispatches each to a worker LLM with its own context window. Workers return structured results that the orchestrator synthesizes. The orchestrator decides when the result satisfies the brief.
        
          
        When to use: Subtasks cannot be enumerated up front — e.g. a research question whose sub-queries depend on what the first searches return.
        
          
        Failure mode: The orchestrator over-spawns redundant workers (or workers duplicate work) because there is no shared scratchpad, inflating token cost without adding coverage.
        
          
        Building effective agents ↗
        
        
        

        
        
          
        
            
        Sequential pipeline
        
            Anthropic · 2024
          
        
          
        Shape: A fixed DAG where each step is an LLM call whose input is the previous step's output, often with deterministic gates (validators, parsers, regex) between steps that can short-circuit the chain. Ends when the last node returns; no agent decides to stop.
        
          
        When to use: The task decomposes cleanly into a known sequence of subtasks and you'll trade latency for higher per-step accuracy.
        
          
        Failure mode: An error in an early step (hallucinated entity, malformed outline) propagates and is amplified by every downstream step — no node ever revisits earlier output.
        
          
        Building effective agents ↗
        
        
        

        
        
          
        
            
        Parallel fan-out · map-reduce
        
            LangGraph docs · 2025
          
        
          
        Shape: A coordinator emits N independent calls (sectioning over different inputs, or voting over the same input) that execute concurrently; a reducer aggregates by concatenation, majority vote, or a final synthesizer LLM. Termination: once all branches return, the reducer fires.
        
          
        When to use: Unit count is known or computable from state (summarize each of 40 docs, screen a prompt with K guardrail checks) and units are independent.
        
          
        Failure mode: Branches that should share context (cross-document deduplication) can't see each other, so the reducer inherits inconsistencies no single branch could detect.
        
          
        LangGraph — graph API (Send / map-reduce) ↗
        
        
        

        
        
          
        
            
        Debate · multi-agent argumentation
        
            Du et al. · 2023
          
        
          
        Shape: Two or more LLM instances generate independent answers to the same prompt, then over R rounds each agent reads the others' previous-round responses and updates its own. Final answers are aggregated by majority vote or a consensus pass — no external judge required.
        
          
        When to use: Factual or reasoning tasks where a single chain-of-thought is unreliable and exposure to a peer's counter-argument empirically pulls answers toward truth (math word problems, factual QA).
        
          
        Failure mode: Confidently-wrong agents anchor the group. In long debates, models converge on a shared incorrect answer — more rounds make accuracy worse, not better.
        
          
        Improving Factuality through Multiagent Debate ↗
        
        
        

        
        
          
        
            
        Evaluator-optimizer loop
        
            Anthropic · 2024
          
        
          
        Shape: A generator LLM produces a candidate; a separate evaluator LLM (or rubric-prompted call) scores it against explicit criteria and returns feedback; the generator regenerates conditioned on that feedback. Loop ends when the evaluator returns "accept" or a max-iteration cap is hit.
        
          
        When to use: You can articulate evaluation criteria clearly enough that the evaluator's feedback measurably improves the next draft — literary translation, code that must pass a stated spec.
        
          
        Failure mode: Evaluator and generator collude on a shared blind spot (both miss the same class of error), so the loop terminates at a confident but wrong "accept."
        
          
        Building effective agents ↗
        
        
        

        
        
          
        
            
        Hierarchical · supervisor of supervisors
        
            LangGraph · 2025
          
        
          
        Shape: A tree where a top-level supervisor routes work to mid-level supervisors, each routing to its own worker pool; control returns up the tree via explicit handoff tools. The top-level supervisor emits the final answer by routing to a FINISH sentinel. Each supervisor sees only its own team's traffic.
        
          
        When to use: Enough specialized teams (research, writing, ops) that giving one supervisor direct access to every worker would blow its context budget and degrade routing.
        
          
        Failure mode: Information needed across teams (a constraint research discovered) gets compressed into the inter-supervisor handoff and is lost before reaching the team that needed it.
        
          
        langgraph-supervisor-py ↗
        
        
        

        
        
          
        
            
        Reflection / critic loop · single-agent
        
            Shinn et al. · 2023
          
        
          
        Shape: One agent attempts the task, receives an external feedback signal (test, tool error, reward, or self-generated critique), writes a short verbal reflection on what went wrong, stores it in an episodic memory buffer, and re-attempts with the reflection prepended. Ends on success or trial-count exhaustion.
        
          
        When to use: Tasks with a cheap, reliable success signal per attempt (unit tests, environment reward, retrieval verification) where the same model can plausibly fix its own mistake once it is named.
        
          
        Failure mode: Without a grounded external signal, self-critique is no more reliable than the original answer — the agent rationalizes the wrong answer or flips a correct one under self-doubt.
        
          
        Reflexion: Verbal Reinforcement Learning ↗
        
        
        

      
        
    
        

    
    
        
      
        §4 · escalation
        
      
        When to escalate single → orchestra
        
      
        
        Multi-agent systems are not a default upgrade. Anthropic's multi-agent research write-up measured
        them consuming roughly 15× the tokens of a chat interaction — token usage alone
        explained ~80% of performance variance in their evaluation. Only escalate when the task
        genuinely needs more capacity than one context window can hold.
      
        

      
          
        
        • Required source material exceeds what one context window can hold even with retrieval — work must be sharded across separate windows to fit.
          • 
        
        • The task is naturally breadth-first: pursue several independent leads in parallel rather than one chain end-to-end.
          • 
        
        • Multiple distinct, complex tool integrations are needed (search + code + database + filesystem) and one agent's tool-selection accuracy degrades when the roster gets too large.
          • 
        
        • The expected dollar value of the answer absorbs an order-of-magnitude token premium over a single chat.
          • 
        
        • Subtask outputs are large artifacts (reports, code, datasets) better written to a shared store than threaded back through conversation history.
          • 
      
        

      
        Counter-indicators (stay single-prompt): the task requires all agents to share the same evolving context, depends on tight real-time coordination, or the per-call latency budget is small.
        

      
        
        Agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats.
        — Anthropic, "How we built our multi-agent research system"
      
        
      
        
        Once intelligence reaches a threshold, multi-agent systems become a vital way to scale performance.
        — Anthropic, "How we built our multi-agent research system"
      
        

      
        
        On handoff: Anthropic recommends having subagents write structured outputs to a filesystem and
        pass lightweight references back to the lead agent rather than threading full transcripts
        through history — explicitly to "minimize the game of telephone" and avoid copying large outputs
        through the conversation. Composer's Agent orchestra mode defaults to summary handoff
        for exactly this reason.
